LAB 02 · WINDOW COMMUNICATION

postMessage Origin Validation

See an untrusted sender message reach a victim's trusted portal, then require the exact sender origin.

OWASP Web MessagingCWE CWE-940LEVEL Medium
01 What it is

Understand the weakness

This weakness occurs when a page processes a postMessage event without checking who sent it. An untrusted page can trigger an action intended only for a trusted partner. The receiver must compare the exact origin and validate the message data before acting.

OWASP: Client-side TestingCWE-940Related: CWE-346
02 The line

Where the unsafe behavior begins

The receiver performs an action after checking only the message type. The missing origin check lets an untrusted sender reach this line.

message-vulnerable.jsVULNERABLE CODE
01function receiveMessage(event) {02  const message = event.data;03  if (!message || typeof message !== "object") return;04  if (message.type !== "SHOW_MEMBER") return;05  showMemberCard(message.name, message.role);06  return true;07}08window.addEventListener("message", receiveMessage);09// receiveMessage never checks event.origin

04 Why it matters

What can go wrong?

An untrusted page can trigger an action intended for a trusted integration. This lab changes only a harmless local card; a real receiver might expose data or initiate a privileged action.

05 The fix

Check sender, then data

Compare event.origin with one exact trusted origin before using the message. Then validate its type and fields.

message-fixed.jsFIXED CODE
01const TRUSTED_ORIGIN = "https://trusted.example";02function receiveMessage(event) {03  if (event.origin !== TRUSTED_ORIGIN) return false;04  const message = event.data;05  if (!message || typeof message !== "object") return false;06  if (message.type !== "SHOW_MEMBER") return false;07  if (typeof message.name !== "string" || typeof message.role !== "string") return false;08  showMemberCard(message.name, message.role);09  return true;10}11window.addEventListener("message", receiveMessage);
